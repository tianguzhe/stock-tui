# CYQ 筹码指标数据源注意事项

> 2026-07-09 使用中天科技(`sh600522`)实测验证。适用于 `WINNER` / `ASR` / `CYQK` 等筹码分布衍生指标的接入前数据源准备。

---

## 一、方案总览

> ⚠️ **2026-07 架构更新**：日K主源已从东财切换到**腾讯 proxy `newfqkline`**(前复权)，东财降为 fallback，TDX 从"日K退路"收窄为**换手率兜底**。本文第二节的东财字段映射作为 fallback / 换手率来源仍是权威参考，继续有效。

| 优先级 | 源 | 职责 | 实测状态 |
|--------|-----|------|---------|
| **主(日K)** | 腾讯 proxy `newfqkline`(前复权) | 历史日K + 换手率 `row[7]` + 振幅(本地算) | ✅ 现行主力 |
| **fallback(日K)** | 东财 push2his(`fields2=f51..f61`) | 腾讯失败时日K + 换手率 f61 + 振幅 f58 | ✅ 2000 根 / 8 年，sh600522 实测 |
| **换手率兜底** | quantbeing/tdx(通达信 TCP 7709) | proxy/东财换手率均不可用时,流通股本本地算 | ✅ v0.1.3，9 内置 host 6 通 |

> 换手率优先级：**proxy `row[7]`** → 东财 `f61`(按日期对齐，匹配率 <80% 判失败) → TDX `Vol/流通股本`。序列换手率(CYQ 用)与 `snapshot.turnover_rate`(实时报价)是两套口径，勿混。

## 二、东财历史日K 接入口诀

### 2.1 URL 与字段映射

```
GET https://push2his.eastmoney.com/api/qt/stock/kline/get
  ?secid={市场}.{裸码}
  &fields1=f1,f2,f3
  &fields2=f51,f52,f53,f54,f55,f56,f57,f58,f59,f60,f61
  &klt=101        # 101=日,102=周,103=月
  &fqt=1          # 0=不复权,1=前复权,2=后复权
  &lmt={上限}
  &end=20500101
```

字段对照（⚠️ **价格≠实时接口**，这里非 ×100 整数）：

| fields2 索引 | 含义 | 单位 | 注意事项 |
|-------------|------|------|---------|
| f51 | 日期 | `YYYY-MM-DD` | — |
| f52 | 开盘 | 小数(元) | 非 ×100 还原，直接 `ParseFloat` |
| f53 | 收盘 | 小数(元) | 同上 |
| f54 | 最高 | 小数(元) | 同上 |
| f55 | 最低 | 小数(元) | 同上 |
| f56 | **成交量** | **手** | **×100 转股数**(与通达信协议对齐) |
| f57 | 成交额 | 元 | 直接使用 |
| f58 | 振幅 | % | — |
| f59 | 涨跌幅 | % | — |
| f60 | 涨跌额 | 元 | — |
| f61 | **换手率** | **%** | **直给，无需本地算**(优于通达信方案)|

> ⚠️ **本接口价格与实时接口区分**：东财实时行情(`push2` 路径)的 `f43` 等为 `×100` 整数。但**历史 Kline 接口** (`push2his` 路径)的 `f52~f55` 为正常小数，勿除以 100。两套路径编码不同，见下方勘误表。

### 2.2 与东财实时行情接口的口径差异（易踩坑）

| 项目 | 实时行情 `push2.eastmoney.com` | 历史 Kline `push2his.eastmoney.com` |
|------|-------------------------------|-----------------------------------|
| 价格编码 | ×100 整数(`f43=4585→45.85`)| 正常小数(`f52=45.85`)|
| 换手率 | `f168`(部分字段不一致) | `f61` 直给 |
| 成交量单位 | 股 | **手** |
| 请求方式 | `fields=f43,f44,...` | `fields2=f51..f61` |

> ⚠️ 初学者容易犯的错：实时行情取惯了 ÷100 逻辑，到历史接口又 ÷100 导致价格缩为百分之一。**两条路径的 parser 必须独立，禁止复用同一个时/除逻辑。**

### 2.3 历史深度实测

- `lmt=2000` 实际返回 **2000 根**，**最早 2018-04-12**（约 8 年）
- 超过 800 根的 `lmt` 也正常返回（2000 已实测通过），未发现服务端强制截断
- 足够 WINNER（需 250 日）、回测（需 500+ 日）所需

### 2.4 前复权对齐

- `fqt=1` 返回**前复权价格**，与 `quantbeing/tdx` 默认前复权**完全一致**
- 2026-07-03 ~ 07-09 逐根收盘价两源吻合（07-03:50.22, 07-06:48.03, 07-07:47.27, 07-08:44.86）
- **WINNER 必须用前复权**，否则除权跳空使成本分布错位

### 2.5 限流与容错

> 该接口偶发限流(返回空或连接 EOF)。批量或重试场景需加退避(至少>1s 间隔)，必要时回退到 `quantbeing/tdx` 兜底。不允许单线程无间隔循环请求。

## 三、quantbeing/tdx 兜底

### 3.1 项目状态

- 仓库：`github.com/quantbeing/tdx`，**v0.1.3**（2026-06-09 发布，单人维护）
- Go 版本要求：Go ≥ 1.21（实测 **Go 1.26.4** 编译通过，依赖仅 `golang.org/x/text`）
- 当前为 v0 阶段，生产接入须保留超时、重试、host failover 与运行指标（观察者模式内置）

### 3.2 host 可用性

内置 9 个 `KnownServers()`，实测 6 个通：

| host | 延迟（PingAll 3s 超时）| 推荐 |
|------|----------------------|------|
| `115.238.56.198:7709` | 102ms | ✅ 主推 |
| `180.153.18.170:7709` | 115ms | ✅ 备选 |
| `123.125.108.14:7709` | 128ms | ✅ 备选 |
| `115.238.90.165:7709` | 140ms | ✅ |
| `110.41.2.72:7709` | 146ms | ✅ |
| `110.41.147.114:7709` | 170ms | ✅ |
| 其余 3 个 | 超时 | 不通 |

> **接入时必须先 `PingAll` 或 `FromBestHost` 测速选最优**，禁止硬编码单个 host。
> 整体延迟在 100~170ms 间，比东财 HTTP（~30~80ms）慢，符合兜底定位。

### 3.3 K 线数据模型

```go
type Bar struct {
    Open     Decimal   // 前复权开盘价
    Close    Decimal   // 前复权收盘价
    High     Decimal   // 前复权最高价
    Low      Decimal   // 前复权最低价
    Vol      float64   // 成交量(股数)
    Amount   float64   // 成交额(元)
    Year, Month, Day  int
}
```

> `Decimal` 提供 `Float64()` 方法转为 `float64`，内部保精度（防浮点累积误差）。
> `Open/Close/High/Low` 默认即**前复权**，无需额外调用复权接口。

### 3.4 与东财的 unite 口径

| 字段 | 东财(fallback) | tdx(换手兜底) | unite 后 |
|------|---------|-----------|---------|
| 价格(开/收/高/低) | `f52~f55` 小数 | `Decimal.Float64()` | 对齐 ✅ |
| 成交量(股) | `f56` ×100(手→股)| `Vol`(直接是股数) | 统一股数 |
| 成交额(元) | `f57` | `Amount` | 对齐 ✅ |
| 换手率(%) | `f61` 直给 | **需本地算**：`Vol / 流通股本 × 100` | 东财更省；tdx 兜底时多用一次 `GetFinanceInfo` |
| 历史深度 | `lmt=2000`(8年) | 单次 `count=800` | 东财更优；tdx 需分页 |
| 前复权 | `fqt=1` | 默认前复权 | 对齐 ✅ |

### 3.5 换手率本地算的原理（兜底路径）

```go
// 1) 拉日K
bars, _ := client.GetSecurityBars(ctx, model.MarketSH, "600522", model.KlineDay, 0, 1)
volShare := bars[0].Vol   // 股数,如 2.2e8 股

// 2) 取流通股本
fin, _ := client.GetFinanceInfo(ctx, model.MarketSH, "600522")
// fin.LiuTongGuBen 单位:股

// 3) 算换手率
turnover := volShare / float64(fin.LiuTongGuBen) * 100
```

> 注意事项：`GetFinanceInfo` 返回的流通股本可能随限售解禁变化。严格做法是用当时实际流通股本，简化方案用"最新流通股本"近似（大部分解禁后不再缩回，误差可接受）。追求极致的回测可叠加 `gbbq`（股本变迁）分段重算。

### 3.6 返回顺序的正确打开方式

⚠️ 常见误解：`GetSecurityBars(ctx, market, code, KlineDay, 0, count)` 的 `start=0` 取的是**最近 count 根，按时间升序排列**。

- `bars[0]` = **这批返回里最旧那根**（如 2026-07-03）
- `bars[len-1]` = **最新那根**（如 2026-07-09）

封装时务必按日期升序输出，不要写死 `bars[0]` 作为"最新价"。

```go
// 正确：取最新价
bars, _ := client.GetSecurityBars(ctx, ...)
latestClose := bars[len(bars)-1].Close.Float64()

// 错误：bars[0] 是最旧的
wrong := bars[0].Close.Float64()
```

## 四、时区与时序注意事项

### 4.1 东八区 vs 洛杉矶

| 用户本地 | 东八区 |
|---------|--------|
| 洛杉矶(PDT=UTC-7) | **+15 小时** |
| 洛杉矶(PST=UTC-8) | **+16 小时** |

- 项目中 `trade_date`、`log_date`、journal 日期统一使用**东八区**
- 东财返回的 K 线日期即为东八区交易日，直接使用不需换算
- 盘中探测时，东八区今天对应的 K 线(如 `2026-07-09`)已经包含开盘数据，不是"未来占位行"

### 4.2 盘中采样差异

- 东财盘初探针（09:28 东八区）抓到的 `vol` 很小
- 同时刻 tdx 协议拉到更大的 `vol`（又过了几分钟，累积量更大）
- **复权后的价格不受采样时点影响**，只有 `vol` 和 `amount` 随时刻累积

> 如果同时在东财和 tdx 各拿一个"今日"的 `vol` 核对发现不一致，先看两侧采样时刻是否在同一分钟——差一分钟盘初累积量就能差数倍。这本身不是两源口径不一致（两源 vol 单位都是股），**不要据此判定数据源出错**。

## 五、接入顺序建议

如果本次是新增筹码指标，**建议分三步走**，每步可验证、可停：

| 步 | 内容 | 验证点 | 风险 |
|----|------|--------|------|
| 1 | 东财 `fields2=f51..f61` 拉日K，落成临时结构，打印逐根字段 | 肉眼确认单位 ✅ | 零 |
| 2 | 用临时日K跑 `WINNER`(持仓衰减模型)，输出首根 vs 末根的值 | 次新股 <60 根应有标记 ✅ | 算法假设可能错 |
| 3 | 指标验证通过后，snapshot 表加 `volume/amount` 列 + 空转 `WINNER`/`ASR`/`CYQK` 落库 | 回读与 CLI 打印一致 ✅ | 加列需走 checklist 全 4 处 |

> **不要在第一步完成前跳过单位校验直接写指标。** 一旦价格/成交量口径错了，WINNER 算出的"获利盘比例"会全部偏移，且难以排查——数值看起来"合理、在 0~100 之间"，但有系统偏差。
